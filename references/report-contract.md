# 步伐报告契约

## 固定结构

标题必须是：

```markdown
# YYYY-MM-DD 步伐
```

随后按以下顺序使用且只使用六个一级内容章节：

```markdown
## 昨日概览
## 做了什么
## 学到了什么
## 暴露的问题、盲区与困难
## 定向补给
## 数据缺口
```

目标长度为 3500–5500 个中文字符，作为可读性目标而不是配额。数据不足时生成更短的透明报告，不得填充或虚构。

## 章节要求

### 本地基线与可选增强完整性

`昨日概览` 和 `数据缺口` 必须分别说明 **Codex 本地会话（CLI/VS Code）** 与 **Claude Code 本地会话** 的覆盖统计。Codex 应用聊天是可选增强：默认环境没有相应工具时静默跳过，不构成数据缺口。只有实际尝试采集时，才列出列表返回数、ChatGPT 候选数、已读取数、纳入数、排除数、未分页范围和窗口完整性；读取失败或列表窗口可能截断时量化披露。除非可验证对应范围，不得使用无条件的“Codex 完整覆盖”。

### 昨日概览

用一句话概括主线，并说明 Codex、Claude 的会话覆盖和总体数据完整性。不要使用原始路径或聊天正文。

### 做了什么

按目标而非聊天顺序合并任务。每项包含：

- 状态：完成、部分完成或受阻。
- 用户希望 AI 完成的目标。
- 可从最终答复、验证结果或动作元数据支持的结果。
- 尚未解决的事项；没有完成证据时不得写成完成。

按**业务主题**合并同一交付链路中的分析、实现、修复、验证和配套重构，不按聊天轮次拆条。同一模块的多次操作或同类问题的多次处理也应合并。过程信息不单独成条：有成果时压入从句；纯讨论只有形成明确方案、决策或选型才保留。

主句使用“完成、实现、修复、重构、优化、配置、梳理、确定、输出”等**成果动词**。只有最终答复与测试、验证、文件动作或可核对结果共同支持时，才算**完成证据**；仅有用户请求时写“待验证”，仅有部分动作时写“部分完成”。只有同一问题反复失败、明确卡住、等待外部依赖或关键决策未定，且复盘结束时仍未解决，才算**真正受阻**。

### 学到了什么

用“提问 → 获得的知识 → 可迁移应用”表达。只有对话中存在学习证据时才写；推测性的收获必须标明“待验证”。

### 暴露的问题、盲区与困难

最多 3–5 项。每项固定包含：

- **观察事实：** 对话中可核对的行为或困难。
- **合理推断：** 从事实得到的有限解释。
- **待验证：** 尚不能从日志确认的部分。
- **影响：** 对效率、质量或决策的具体影响。
- **下一步：** 一个可执行的小动作。

不得进行心理、人格、动机或固定能力诊断，不得把一次提问泛化为长期特征。

### 定向补给

总计推荐 1–4 项最高价值内容，避免凑数和重复。每项包含：

- 类型：文章、章节、官方文档、GitHub 项目、skill 或 plugin。
- 可点击的标题与当前可访问链接。
- 它针对的具体问题和推荐理由。
- 预计阅读或试用时间。
- 对 skill/plugin：可验证时标明已安装、可安装或可用性待验证；只推荐，不执行安装。

技术事实优先使用官方文档、原始论文或项目仓库。当天问题涉及书籍、思维、决策、习惯或生活主题时，可推荐书籍的具体章节、文章或实践材料；不得默认只推荐技术资料。链接必须在本次运行中核验，不得凭记忆虚构。

### 数据缺口

量化报告来源覆盖、锁定/不可读文件数、畸形记录数、去重数、截断字符数和选择性未精读范围。只写统计和影响，不暴露绝对路径、文件名、消息正文或私有项目标识。

## 证据与隐私

- 使用“观察事实 / 合理推断 / 待验证”区分证据强度。
- 搜索查询只能来自 `search_brief` 或不超过 240 字符的等价脱敏摘要。
- 发布前扫描 Windows/Unix 绝对路径、用户名、仓库名、代码、密钥、token、密码和带凭据或敏感查询参数的 URL。
- 原始日志和局部回读内容只在本机处理，不进入联网查询。

## 发布门槛

仅当标题日期、六节、长度策略、链接和隐私检查全部通过后，才把临时草稿用原子替换发布到 `D:\Web\new_think\YYYY-MM-DD步伐.md`。任何检查失败都不得改动已有同日报告；全部通过后允许原子刷新并替换已有同日报告。

Notion 是独立的可选发布阶段。它只能在本地原子刷新成功且用户明确要求发布时执行；Notion 失败不得影响已经验证的本地报告。
